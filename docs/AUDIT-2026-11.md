# Brutal audit: KS-LEARN as a full-stack edtech product for children and teens

**Date:** November 2026 · **Version audited:** 2.6.0 (`8d956a5`) · **Lenses:** full-stack web
architect, 15-year classroom teacher, NEP 2020 / NCF 2023 curriculum expert, AI-era learning
coach.

This is not a code-style review. It asks three harder questions:

1. **Will it work, safely and reliably, for the children it claims to serve?**
2. **Would a good teacher use it, and does it teach what NEP 2020 actually asks for?**
3. **Is it ready to be a personalised coach in the AI era, or only a quiz app with a story
   screen?**

The short answer: **the engineering craft is well above average; the learning product is not
yet ready for the claim “class 3–9, personalised mastery learning.”** It is a credible,
unusually privacy-respecting *practice* app. It is not yet a curriculum, an assessment system,
a classroom tool, or an AI-era coach. Several defects would cause real harm in use — including
one that means the deployed site is probably not the app that was tested.

## 1. The finding that outranks everything else: the deployed app is stale

The repository contains three different builds:

| File | Size | What it is |
|---|---:|---|
| `index.html` (repo root) | 550 KB | An **old build**: no consent flow, no labs, no Grow hub, no wellbeing, no quests. |
| `dist/ks-learn.html` | 873 KB | Current single-file app (Phase 5). |
| `dist/pwa/index.html` | 869 KB | Current installable PWA. |

`.github/workflows/static.yml` deploys the **whole repository** (`path: '.'`) to GitHub Pages.
It does not run `npm ci`, `npm test`, `npm run build`, or `npm run verify`. On a standard Pages
deployment, `/` therefore serves the stale root `index.html`, not the current app.

**Impact.** A child or parent opening the live URL can get a pre-consent, pre-labs build. That
is a DPDP and safeguarding failure, not a cosmetic one. It is also a data-loss path: the old
build's `sanitize()` does not know the Phase 4/5 fields, so opening it and saving can silently
drop labs, wellbeing, quests and story progress.

**Remediation applied on this audit branch (P0-1):**

- `.github/workflows/static.yml` now runs `npm ci` and `npm run check` (content audit, 122 unit
  tests, build, dist policy verification) and uploads **only `dist/pwa`**. A failing check stops
  deployment.
- `.github/workflows/ci.yml` runs the same check on every pull request and non-main push, and
  fails if the committed `dist/` does not match a fresh build — the root cause of three
  divergent builds.
- The stale 550 KB root `index.html` is replaced by a 1.5 KB bilingual redirect to `dist/pwa/`, so
  even a branch-based Pages setting cannot serve the pre-consent app.

**Remaining requirement:** confirm the Pages environment URL and test it from a clean browser.
A deployment is not verified because the repository contains `dist/`.

## 2. Architecture and delivery

### 2.1 Single-document persistence plus a 15-second heartbeat (P0 reliability)

`src/ui/app.js` writes the whole state every 15 seconds on child screens, and every tab that
receives a `storage` event discards its in-memory state, rebuilds skills, sets `run = null`,
closes the parent area, and re-renders (`src/ui/app.js:925-936`).

With two tabs open — a normal thing on a shared phone or a parent's laptop — each tab's
heartbeat overwrites the other, and the other tab aborts the current session and reloads. A
parent reading the report gets kicked out. A child mid-question sees the screen reset. This is
not hypothetical; it is the designed interaction of two independent timers writing one key.

**Fix direction:** a single-writer lease (Web Locks API with a localStorage fallback), write
only when the document actually changed, and never treat a storage event as “abort the
session”; merge counters or show a non-destructive notice. Add a two-tab Playwright test.

### 2.2 Plaintext child data on a shared origin (P1 privacy)

The whole learning record, consent receipt and guardian account hashes sit in
`localStorage['kslearn.v2']` in plaintext. On GitHub Pages, **all repositories under the same
`*.github.io` origin share localStorage**. A different app on that origin can read the key.
Even on a dedicated origin, any injected script (there is none today, but future packs or
extensions) can read it.

The DPDP Act requires reasonable security safeguards; device-local plaintext is a defensible
*risk acceptance* only if it is written down and paired with mitigations. Recommended:

- host on a dedicated origin, not a shared user-site origin;
- encrypt the document at rest with AES-GCM, wrapping the key with a guardian-derived key and
  keeping a child-session key in memory; or, at minimum, document the threat model and offer
  “erase on close”;
- never include guardian account hashes in a routine backup unless the parent explicitly
  chooses “full backup”.

### 2.3 Schema versioning and backups (P1)

`VERSION` is still `2` after four phases of new fields. Backups have no checksum, no schema
manifest, no author/version display, and `importText()` accepts any shaped JSON that passes
`sanitize()`. Two consequences:

- an older build silently discards newer fields on import/save (see §1);
- a corrupted-but-parseable backup can look like a valid restore and quietly reduce progress.

**Fix:** bump to schema 3 with a `features` map, add a SHA-256 of the canonical state to
exports, show a restore preview (“this file: 131 skills, 428 days, 2 guardian settings”), and
keep the previous two automatic snapshots (not just one manual undo).

### 2.4 One monolithic application shell (P2 maintainability)

`src/ui/app.js` is 960 lines and owns routing, session rendering, scaffolding UI, rewards,
parent area, settings, backup, packs, consent/account orchestration, voice, and global
teardown. The new modules are cleaner, but every feature still has to remember
`voice.stop(); labsUI.stopLab(); wellbeingUI.stop();` in `render()` or leak timers.

**Fix direction:** an explicit view contract (`mount`, `unmount`, `hashchange`) and a router
table; a state container with transactions instead of a mutable module-level `state`; JSDoc or
TypeScript for the state shape. This is not urgent for a solo project, but it is why the next
three features will be slower and riskier than the last three.

### 2.5 Performance and bundle budget (P2)

- 873 KB HTML, **204 KB gzip / 162 KB brotli**; the build gate is 900 KB uncompressed, leaving
  only ~27 KB of headroom.
- A realistic maximum state (6,000 log rows, 3,000 skills, 400 day records) serialises to
  **~542 KB** and is stringified every 15 seconds.
- No code splitting is possible by design (single-file promise). That is a legitimate
  constraint, but it means every future feature needs an explicit budget and a “delete
  something” rule.

The single-file promise is a genuine strength for USB/offline distribution, but “one file”
must not become “one unbounded file”.

### 2.6 Release gate does not exercise a browser (P1 process)

`npm run check` is content audit + unit tests + build + dist verifier. It does **not** run
`tools/e2e.mjs`; Playwright is not a dependency, and CI has no browser. The verifier proves
the bundle is CSP-clean and small, not that a child can consent, start a mission, restore a
backup, or use the app offline. Every UI regression is currently caught only by manual
testing or a one-off jsdom drive.

**Fix:** add Playwright as a dev dependency, run the existing e2e suite in CI on Chromium, and
add axe-core accessibility assertions. This is the highest-leverage engineering investment
after the deployment fix.

## 3. Learning engine: where the pedagogy breaks

### 3.1 Content coverage contradicts the product claim (P0)

Measured from `src/content/index.js`:

| Class | Skills | What a child actually gets |
|---:|---:|---|
| 3 | **4** | Four maths skills; no English, Hindi, science, reasoning, coding, social science. |
| 4 | 28 | Reasonable maths/language; thin science and social science. |
| 5 | 54 | The only genuinely broad class. |
| 6 | 29 | Maths/language thin; science/social science partial. |
| 7 | 13 | No English, one Hindi, one science, no class-7 maths beyond six topics. |
| 8 | **3** | Squares/roots, equations, one civics skill. No science, English, Hindi, geometry. |
| 9 | **0** | The setup screen does not even offer Class 9; Settings does. |

A Class 8 child cannot use this app for most of Class 8. A Class 3 child gets four maths
drills and is then pushed into Class 4+ content by the planner's fallback (see below). The
README's “class 3–9” is not true in the artefact.

This is not a content-polish issue. It invalidates the core promise, the roadmap, the
parent report and the NEP claims. **No amount of AI coaching can compensate for a missing
curriculum.**

### 3.2 The “no ceiling” fallback quietly teaches above grade level (P1)

`frontier()` returns `within.length ? within : open` (`src/core/planner.js:22-23`). If a class
has no skills in a strand — Class 3 English, Class 8 science — it silently offers the nearest
higher-class skills. There is no “content not available yet” state and no parent-visible
diagnostic. For a class 3 learner this can mean Class 4–8 language or science text.

**Fix:** cap the fallback at `cls + 1`, label it “a peek ahead” only with guardian consent, and
show a clear “this subject is not available for this class yet” card rather than pretending.

### 3.3 Mastery is awarded too easily and too early (P0)

`masteryReady()` requires `p ≥ 0.95`, four graded answers (`minN = 4`), two correct in a row,
and `retention(s.p, 0) ≥ 0.8` (`src/core/mastery.js:39-41`). The last condition is evaluated at
**zero days**, so it is a constant for any `p ≥ 0.95` — it does not test retention at all.

With the default BKT parameters, four cold correct answers can push a skill over 0.95 in a
single short sitting. There is no delayed retrieval, no mixed-format check, no explanation, no
transfer item, and no requirement that the skill be recalled after a gap. Calling that
“mastered” overstates what the app knows; a parent reading “mastered” will reasonably believe
the child can still do it next month.

**Fix (minimum):**

1. require at least one **delayed** correct check (≥ 2 days after first mastery-level evidence)
   before the state becomes `mastered`; until then show “secure today / needs a check”;
2. require at least two item formats (e.g. numeric + explanation/MCQ or order);
3. compute the retention gate from `gapDays(s.last, day)`, not zero;
4. add a transfer item or “explain why” rubric before the mastery badge.

### 3.4 One wrong review answer destroys mastery (P0)

In `update()` (`src/core/mastery.js:77-80`), a single wrong answer on a mastered skill sets
`s.m = false`, `s.due = null`, `s.st = 0`, `s.p = min(s.p, 0.5)`. The file's own header says “a
single bad day does not erase weeks of work.” It does exactly that: one slip in a review
removes the mastered state and halves the estimate.

For a child, this is demoralising and pedagogically wrong: a slip is not the same as
forgetting, and a single item is noisy evidence. Use a **“needs review”** state, keep mastery
history, require two failures or a failed delayed check before demotion, and show a calm
“let's revisit this” path. The current design punishes the exact behaviour the app claims to
reward (returning to review).

### 3.5 The weekly “test” changes the learning state (P1)

`startTest()` creates a session with `{ test: true }`, but `session.answer()` always calls
`update(st[sk.id], ...)` and logs/counts stars (`src/core/session.js:64`). Test answers can
trigger `mastered`, `stuck`, review demotion, stars and the gold reward. A test is therefore
also practice, and a bad test day can demote mastered skills.

Either make the test a **measurement-only** mode (separate evidence, no state mutation) or stop
calling it a test and name it “mixed practice”. Do not blur the two. The test sampler also
picks with `(i * 7 + random) % pool.length`, which can repeat skills and does not guarantee
coverage of the syllabus.

### 3.6 Question formats are narrow for a competency-based curriculum (P0 pedagogy)

Measured across 131 skills: **65 MCQ, 51 numeric, 4 fraction, 4 text, 4 order, 4 match**. There
is no constructed explanation, no multi-step working, no reading passage with inference
questions beyond a handful, no writing, no oral reading, no project, no experiment design, no
data interpretation, no source analysis.

That is a practice engine for recall and procedure, not a competency engine. NEP/NCF ask for
application, analysis, creation, communication and collaboration; the item bank cannot
evidence them. Adding AI-generated explanations on top would not fix an assessment design that
never asks the child to explain, justify, build or critique.

### 3.7 Typed-answer checking punishes normal child input (P1)

`norm()` lowercases, trims and collapses spaces but does not strip terminal punctuation,
normalise Unicode (NFC/NFD), or tolerate common Hindi spelling variants (`अम्माँ` vs `अम्माँ`,
anuśvāra/chandrabindu choices). “Delhi.” is marked wrong; a correct Hindi word typed with a
different matra sequence can be marked wrong. For language learning this is a direct
disincentive. Add Unicode normalisation, punctuation tolerance, and a “did you mean…?” path
that never silently marks a correct idea wrong.

### 3.8 Planner sequencing and mission design (P1)

`buildMission()` always prioritises maths, then one language, then one rotating subject, with
fixed weights. It is deterministic but not child-led, not project-led, and does not account
for the child's own goal or teacher plan. The “mixed revision” fallback keeps a child busy on
mastered skills when the syllabus has holes but no unlocked frontier. That is honest
maintenance, but it is not progress.

The session also measures `ms` from question mount to answer (`src/core/session.js:60`) with no
visibility pause; leaving a tab open for two minutes records a 180-second response time and
distorts the parent's “average time”.

### 3.9 Reward economy is saturated and externally controlling (P2)

A child earns +1 star per correct answer, +5 for mastery, 5 gold for a finished session of 8+,
a mission bonus of 10 + 2×streak (up to 24), 2 for a comeback, 2–5 for quests, 2 for a story.
A typical day can produce 30–50 stars. Level 9 is 3,000 stars, reachable in a couple of months;
after that the reward system has no next horizon. The streak flame and `streak30` badge create
pressure the app elsewhere says it does not want.

This is not “gamification done well”; it is a point economy that can crowd out intrinsic
motivation (the overjustification effect). Keep stars as a lightweight signal, add a spending
or choice sink, or move to mastery/competence feedback and child-chosen goals. At minimum, let
the child hide the streak.

## 4. NEP 2020 / NCF 2023 alignment

### 4.1 What NEP/NCF actually ask for

NEP 2020 and NCF 2023 are not a syllabus to be converted into MCQs. Their operative ideas are:

- the **5+3+3+4** stage structure and stage-appropriate pedagogy;
- **competency-based** learning outcomes, not content coverage;
- **holistic, multidimensional assessment** and a Holistic Progress Card (HPC), including
  self-assessment, peer assessment, projects and portfolios;
- **foundational literacy and numeracy** (NIPUN Bharat) with oral reading fluency and numeracy
  checks by Grade 3;
- **mother tongue / home language** as the medium in early years and the three-language formula;
- **experiential, inquiry, art-integrated, sports-integrated, toy-based** learning;
- **no hard separation** between arts and sciences, curricular and co-curricular, vocational
  and academic;
- **critical thinking, creativity, communication, collaboration, curiosity, citizenship,
  environmental awareness, financial literacy, digital literacy, computational thinking, AI**;
- **inclusion** and equity for SC/ST/OBC, girls, children with disabilities, and multilingual
  learners;
- **teacher agency**, school autonomy, and continuous professional development;
- **Indian knowledge systems** integrated with rigour, not as decoration;
- **safety, privacy, and child rights** in digital learning.

### 4.2 Alignment matrix

| NEP/NCF expectation | Evidence in KS-LEARN | Verdict | What is missing |
|---|---|---|---|
| 5+3+3+4 stage model | Class field 3–8 in setup, 3–12 in settings; auto-advance every April | **Misaligned** | No foundational (1–2) or secondary (9–12) content; class 3/8 holes; no stage-specific pedagogy. |
| Competency-based outcomes | Skill titles + BKT probability | **Weak** | No learning-outcome codes, competency descriptors, rubrics, or evidence types. |
| Holistic Progress Card | Mastery %, stars, badges, weekly accuracy | **No** | No multidimensional report, self/peer assessment, portfolio, project, or teacher comment. |
| FLN by Grade 3 | Starts at Class 3 with 4 maths skills; no oral reading or numeracy fluency | **No** | No baseline diagnostic, oral reading fluency, number sense interview, or remediation pathway. |
| Mother tongue / three languages | English and Hindi only; default `bi` renders **English** content with occasional Hindi glosses (`src/core/i18n.js:34-40`) | **Weak** | No Maithili/Bhojpuri/Magahi or other Indian language; default is English-dominant, not home-language-first. |
| Experiential/inquiry/arts/sports/vocational | 4 Curiosity Labs, 4 stories, 5 wellbeing layers | **Partial, promising** | No arts, music, sport, vocational, fieldwork, making, or long-term project. |
| Critical thinking/creativity | Reasoning strand 9 skills; story dilemmas | **Partial** | Mostly MCQ/recall; no argument, source evaluation, design, or open-ended creation. |
| Digital literacy / computational thinking / AI | Coding 9 skills; AI 2 skills; `g.verify` | **Thin** | No data literacy, algorithms beyond loops, networks, AI ethics depth, model lifecycle, media literacy. |
| SEL / mental health | Panchakosha pauses, feelings, stories | **Partial, good intent** | No teacher-led circle, no screening/referral, no family/community context, no evidence base documented. |
| Inclusion / accessibility | Reduced motion, contrast, large targets | **Partial** | No dyslexia/low-vision/motor accommodations, no regional language, no captions/audio-first path, no UDL. |
| Indian knowledge systems | Panchakosha names and five layers | **Decoration risk** | No source grounding, teacher notes, local knowledge, or integration with science/maths. |
| Environmental / citizenship / financial literacy | 1 environment skill, 2 civics, 1 money/banks | **No** | No coherent strand, project, or local civic action. |
| Teacher agency / school use | Parent-only, one child per device | **No** | No teacher account, class roster, assignment, observation, or printable report. |
| Safety / privacy | Strong DPDP consent, no tracking, PIN parent area | **Strong** | Stale deployment, plaintext origin risk, no safeguarding escalation pathway. |

### 4.3 The teacher's verdict (15 years in the classroom)

> “I can see myself giving this to a child for 15 minutes of practice after a lesson. I cannot
> use it to plan a lesson, diagnose a class, run a group activity, assess a project, or talk to
> a parent with evidence beyond a percentage. The scaffolding is the best part: it responds to
> a wrong answer like a patient teacher. The worst part is that it calls four quick correct
> answers ‘mastery’ and then takes that away on one bad day. No experienced teacher would do
> that.”

What a teacher needs before this is a classroom tool:

1. **A unit map** from NCERT/SCERT chapter → learning outcomes → skills → item types.
2. **A 40-minute lesson shape**, not only a 15-minute mission: hook, explain, guided practice,
   independent practice, exit ticket, reflection.
3. **Diagnostic and remediation**: a short baseline, error-pattern grouping, printable small-group
   plan.
4. **Assessment evidence**: oral reading, writing, project, performance task, self/peer rubric.
5. **A parent/teacher conference artefact**: one page, strengths, evidence, next step, no ranking.
6. **Classroom management**: group codes, no personal accounts for every child, teacher control.

None of that is a “nice to have” for NEP; it is the difference between a practice app and a
learning system.

### 4.4 The NEP expert's verdict

The app uses the **vocabulary** of NEP (mastery, competency, multilingual, holistic, SEL,
AI) but not yet the **architecture** of NEP:

- “Mastery” is a probability threshold, not a demonstrated competency.
- “Holistic” is stars and badges, not a multidimensional profile.
- “Multilingual” is English with Hindi glosses, not home-language learning.
- “AI” is two multiple-choice questions, not AI literacy.
- “Inclusive” is responsive CSS, not Universal Design for Learning.
- “Teacher” is absent.

The fastest route to credibility is not more features. It is a **curriculum and assessment
spine**: outcome codes, evidence types, rubrics, and a report a teacher can defend.

## 5. AI-era readiness

### 5.1 What exists

- 9 coding skills: sequences, loops, variables, conditions, binary, some loop tracing.
- 2 AI-literacy skills: “what AI is” and “using AI wisely”.
- 1 verification skill: “check before you believe”.
- No data literacy, statistics/probability beyond percentage/average, no model evaluation, no
  bias, no privacy engineering, no prompting, no human-in-the-loop, no AI project.

### 5.2 What “AI-era” actually requires

For children, AI literacy is not “how to use a chatbot”. It is:

1. **Data literacy** — what a dataset is, sampling, missing data, bias.
2. **Algorithmic thinking** — decomposition, abstraction, debugging, efficiency.
3. **Model literacy** — training, inference, probability, uncertainty, hallucination.
4. **Evaluation** — how to test a claim/model, precision/recall in age-appropriate form.
5. **Human judgement** — when not to automate, accountability, escalation.
6. **Ethics and rights** — privacy, consent, copyright, deepfakes, bias, labour.
7. **Creation** — build a small classifier/rule system, document it, critique it.
8. **Metacognition** — when to use AI, when to think alone, how to verify.

The current app teaches (1) barely, (3) two facts, (4) one habit. That is a start, not a strand.

### 5.3 Do not call it an AI coach yet

There is no model in the bundle, and that is the right default for low-end offline devices.
A “coach” can be excellent without an LLM: a deterministic pedagogical agent that uses local
evidence to run a five-minute goal-setting and reflection cycle. That is the blueprint in
[COACH.md](COACH.md). An on-device LLM is an optional later pack, not a prerequisite, and must
never be the source of curriculum facts.

## 6. Accessibility, safety, privacy

### 6.1 Accessibility (P1)

Strong: semantic buttons, 48–56 px targets, `aria-live` feedback, progressbar roles, reduced
motion, dark mode, measured contrast (muted text 5.47:1 on background; 5.98:1 on surface).

Gaps:

- The reward sheet is `role="dialog"` without `aria-modal`, no focus trap, no Escape, no focus
  return (`src/ui/app.js:302-304`). The wellbeing break sheet has `aria-modal` but does not move
  focus into it or trap it.
- No skip link; the fixed bottom nav is after main content in DOM, so keyboard users tab
  through a long page before navigation.
- No font-size/line-spacing control, no high-contrast theme beyond system dark mode.
- No screen-reader test in CI; no axe-core.
- Bilingual labels in 5 bottom tabs at 320 px are at risk of wrapping/clipping; Hindi
  Devanagari needs more line height than 1.1 in tabs.
- The class 3 learner is text-heavy; there is no reliable audio-first path (browser TTS voice
  availability for Hindi is inconsistent).

### 6.2 Safeguarding (P1)

- The “still heavy” break reply says “tell a grown-up you trust”, which is good, but there is no
  visible safeguarding policy, no named adult/school contact, no escalation or log, and no
  guidance for the parent if a child discloses.
- Moral stories handle consequences well, but there is no teacher discussion guide, no
  safeguarding note for sensitive topics (theft, food, bullying, phone messages).
- Panchakosha is presented as five quick cards. A 15-year teacher would call that a **routine**,
  not a curriculum; it needs facilitation notes and a clear “not therapy” boundary.

### 6.3 Privacy strengths and residual risks

Strengths: purpose-by-purpose consent, digest-checked record, 12-month reconsent, withdrawal,
erasure, local guardian account, no analytics, no ads, CSP `connect-src 'none'`, no external
requests, path/choice/reflection content never stored, heartbeat timestamp not persisted.

Residual risks:

- plaintext storage on a potentially shared origin (§2.2);
- backup files contain consent/account hashes and the full answer log; parents may share them
  without understanding;
- `window.claude.use('tts')` in `src/ui/app.js:167` is a host-platform speech path used when
  the browser has no speech synthesis. It may send question text to the host service, which
  contradicts “nothing leaves the device” unless the artifact context is explicitly excluded.
- curated PhET links open an external site (`target=_blank`, `noopener`), with no “you are
  leaving the offline app” warning. For children, that is a supervision decision, not a neutral
  link.
- no encryption, no remote wipe, no device-binding; a lost phone is a data-loss event.

## 7. What is genuinely strong

Do not throw these away in the remediation:

1. **The offline/CSP discipline is rare and valuable.** A single file, no runtime dependency,
   hash-pinned script/style, network forbidden by policy and verifier. This is the right
   architecture for Indian classrooms with poor connectivity and shared devices.
2. **The DPDP implementation is better than most commercial edtech.** Purpose-level consent,
   guardian ceremony/school token, digest, renewal, withdrawal, erasure, no dark patterns.
3. **Scaffolding is the pedagogical jewel.** Hint → prerequisite/worked example → retry, with
   fading and weighted evidence, is a genuine teaching move, not a gamified sticker.
4. **Phase 4/5 interaction quality is high.** Labs, breathing circle, branching stories and the
   five-layer wheel are thoughtful, accessible, and locally built.
5. **The test suite (122 tests) and the content audit are real.** They catch structural errors
   that most edtech ships with.
6. **The parent view is calm and non-comparative.** No leaderboard, no ranking, no ads.

The product's best future is **“the most trustworthy offline practice and reflection companion
for one child”**, not “an AI school in a box”. That is a defensible, valuable niche.

### Phase 6B — NEP spine and teacher layer (~4–6 weeks)

- Learning-outcome codes and competency descriptors for every skill (NCERT/SCERT mapping).
- Holistic Progress Card export: strengths, evidence, next step, child self-reflection, parent
  comment; one printable page; no rank.
- Teacher mode: class code, group summary, error-pattern grouping, printable small-group plan;
  no child personal accounts required.
- FLN baseline for Class 3: oral reading fluency passage + number sense interview + remediation
  path.
- Regional language pack architecture (Maithili/Bhojpuri/Magahi first for Bihar), with
  community review, not machine translation alone.
- UDL accommodations: font size/spacing, dyslexia-friendly option, audio-first mode, reduced
  distraction, captions for labs.

### Phase 6C — Coach and AI literacy (~4–6 weeks)

- Deterministic coach (see [COACH.md](COACH.md)): weekly goal, plan, check-in, reflection,
  transfer task; no free-text storage; no anthropomorphic dependency.
- New AI-literacy strand: data, models, evaluation, ethics, creation; at least 12 skills across
  Classes 5–8, with projects and teacher notes.
- “AI use” policy for the child: when to use a tool, how to verify, what never to paste.
- Optional on-device LLM pack only after eval; separate download, hash-verified, no network,
  strict retrieval and refusal tests.

### Phase 6D — Evidence and scale

- 12-week efficacy study: pre/post competency tasks, delayed retention at 30 days, transfer,
  self-efficacy, help-seeking, equity by gender/language/device.
- Content expert and safeguarding review; bias audit of item bank.
- Field diagnostics with consent (local-only error summary, parent opt-in).
- Performance budget per release; bundle “delete something” rule.

## 10. Bottom line

**Keep:** the offline architecture, CSP, DPDP consent, local guardian account, scaffolding,
labs, stories, wellbeing interactions, non-comparative parent view, and the test discipline.

**Stop claiming:** “class 3–9” until coverage is real; “mastered” until it means durable,
transferable competence; “bilingual” until the default is genuinely home-language-first;
“holistic” until there is an HPC; “AI” until there is AI literacy.

**Do first:** deploy the right build; fix cross-tab data loss; fix mastery/demotion/test
semantics; make content coverage a release gate; add a real browser/a11y test gate.

**Then:** build the NEP spine (outcomes, HPC, teacher layer, FLN, regional language) and only
then the coach. The coach should be a deterministic pedagogical agent first, and an LLM only if
it can be evaluated, constrained and run on the devices children actually have.
